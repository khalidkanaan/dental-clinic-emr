# Dental Clinic — Patient Management (Flutter)

A simple, modern, single-clinic patient management app. It talks **only** to the
existing Cloudflare Worker API (never directly to Cosmos DB) and focuses on one
workflow: *Search Patient → Open Patient → Review Visit History → Add/Edit Visit*.

Targets **Android, iOS, and Windows**. English + Arabic (full RTL). Light + dark.

---

## 1. Getting started

This repository contains the application source (`lib/`, `pubspec.yaml`,
`l10n.yaml`, ARB files). Platform runner folders are generated by Flutter.

```bash
# 1. Generate the platform folders (android / ios / windows) in place.
#    Existing lib/, pubspec.yaml and l10n.yaml are preserved.
flutter create . --platforms=android,ios,windows --project-name dental_clinic

# 2. Fetch dependencies.
flutter pub get

# 3. Generate the localization sources (creates lib/l10n/app_localizations.dart).
flutter gen-l10n

# 4. Run.
flutter run                 # mobile / attached device
flutter run -d windows      # Windows desktop
```

> If your editor shows errors about `AppLocalizations` before the first build,
> run `flutter gen-l10n` — that file is code-generated from the ARB files.

### API base URL

The base URL (including the `/v1` prefix) is centralized in
`lib/core/config/app_config.dart` and can be overridden at build time:

```bash
flutter run --dart-define=API_BASE_URL=https://your-worker.example.dev/v1
```

Default: `https://khalo-cosmos-api.khalid-kanaan-ca.workers.dev/v1`

### API token

On first launch the app shows a setup screen to enter the **App API token**.
It is stored with `flutter_secure_storage` and sent as
`Authorization: Bearer <token>` on protected requests. It is never written to
source, assets, `shared_preferences`, or logs. You can reset it from
**Settings → Reset API token**.

## 2. Architecture

```
UI (screens/widgets)
  → Riverpod controllers (application/)
    → Repositories (data/)
      → ApiClient (Dio)
        → Cloudflare Worker
```

* **State management:** Riverpod 3 (`Notifier` / `AsyncNotifier` /
  `FamilyAsyncNotifier`, manual providers — no code generation / build_runner).
* **Networking:** a single `ApiClient` over Dio centralizes base URL, timeouts,
  the auth interceptor, JSON decoding, and error normalization. Widgets never
  build requests directly.
* **Errors:** every failure becomes a typed `ApiException` (code + status +
  `Retry-After` + `X-Request-Id`). The UI translates the code into a localized
  message via `localizedError(...)`; raw API JSON is never shown. The request id
  is available under a collapsible *Technical details* section after an error.
* **UI package:** `material_ui` — the official standalone Material 3 library
  (Material was decoupled from the Flutter core). It is a drop-in for
  `package:flutter/material.dart`.

```
lib/
  app/            app.dart, router.dart, theme.dart
  l10n/           app_en.arb, app_ar.arb  (+ generated app_localizations.dart)
  core/           api/, config/, storage/, formatting/, error/, widgets/
  features/
    patients/     data/ application/ presentation/
    visits/       data/ application/ presentation/
    settings/     application/ presentation/
    health/       data/ application/
    setup/        application/ presentation/
```

## 3. Money (JOD)

The API stores every amount as a **non-negative integer of hundredths of one
JOD** (`5000` → `50.00 JOD`, `12550` → `125.50 JOD`). All conversion is done
with integer arithmetic and string parsing — never floating-point — in
`core/formatting/currency_formatter.dart`:

* User input (`50`, `50.0`, `50.00`, `125.5`, Arabic digits) → integer hundredths.
* More than two decimal places is rejected.
* Amounts stay as integer hundredths across the domain layer; they are formatted
  only for display.

## 4. Concurrency & idempotency

* **Creates** (`POST /patients`, `POST .../visits`) send an `Idempotency-Key`
  (UUID v4). The key is generated once per form and **reused on retry**, so a
  timed-out create is never duplicated.
* **Updates / deletes / archive / restore / purge** send `If-Match: <version>`
  (the `version` = Cosmos `_etag` stored on each model). On HTTP **412** the app
  shows *"This record was changed elsewhere."* with **Reload Latest / Cancel** —
  it never silently overwrites newer data.

## 5. Archive / restore / purge

* Removing a patient is **Archive** (not delete): hidden from the directory,
  visit history preserved, restorable. Archived patients appear only when
  *Show archived patients* is on, with a muted **Archived** chip.
* **Permanently Delete** appears only for an already-archived patient, in the
  overflow menu. The backend requires the patient to be archived **and** to have
  no visits; the app surfaces those requirements rather than auto-deleting
  visits.

## 6. Localization & RTL

* All user-facing strings are in `lib/l10n/app_en.arb` / `app_ar.arb`. No
  hard-coded English in widgets. Patient-entered content is never translated.
* Switching language in Settings applies immediately; Arabic renders full RTL
  (navigation, back arrows, directional chevrons, alignment, dialogs).

## 7. Responsive layout

The same navigation model (Directory → Details → Forms) is used on phone and
Windows. On Windows, extra width becomes whitespace via centered
max-content-width wrappers — not extra panels. `window_manager` only sets an
initial window size/centering; the layout stays responsive and usable around
800×600. On mobile, forms are full-screen and remain usable with the keyboard
open.

## 8. Notes / deviations

* `material_ui ^1.1.0` is a relatively new standalone package. If your Flutter
  channel predates the Material decoupling, either upgrade Flutter or switch the
  imports from `package:material_ui/material_ui.dart` back to
  `package:flutter/material.dart` (the widget APIs are identical).
* Patient create/edit and visit add/edit are presented as full-screen routes on
  every platform (constrained to ~600px on Windows) to keep one consistent
  navigation model, rather than a separate desktop dialog stack.
